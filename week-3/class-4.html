No. It is an open standard; many apps and many servers use it.
What else can an MCP server offer?
Any tool: a calendar, a database, a company's internal search.
Why not give the agent all three tools?

Connect
async and await

MCP tools are asynchronous

from langchain.mcp import MCPAdapter async with MCPAdapter("https://docs.langchain.com/mcp") as adapter: docs_tools = await adapter.list_tools() docs_agent = create_agent(llm, tools=[docs_search], middleware=[shorten_tool_results]) answer = await docs_agent.ainvoke({"messages": "How do I add short-term memory?"})

An MCP tool talks to a server over the internet, so you await it, and the agent runs with await agent.ainvoke(...). In Colab, await works directly in a cell.

Questions that may come up0:10 to 0:25, then you code
What does await do?
It waits for a slow operation, like a network call, to finish, without blocking everything else.
What happens with invoke instead of ainvoke?
An error: MCP tools have only an asynchronous version.
Do the tools still work after the async with block?
Yes. The docs say the tools stay callable after the block ends.
Why the beta warning?
langchain.mcp is new in LangChain 1.4. It works, but its API may still change.
Too big for the context
Day 1 again

One search: 52,000 characters

@wrap_tool_call async def shorten_tool_results(request, handler): result = await handler(request) # run the tool result.content = str(result.content)[:3000] # keep the first 3,000 characters return result

The free Groq plan allows about 8,000 tokens a minute; one docs search is more than that. The same @wrap_tool_call as the Day 1 guard, written with async def and await, because MCP tools are asynchronous.

Questions that may come up0:25 to 0:35, then you code
Why is the result so big?
The docs server returns many full sections of documentation for one query.
Does cutting lose the answer?
Sometimes. The first sections are the most relevant, so 3,000 characters is usually enough.
Why async def here?
In an asynchronous agent, a plain function middleware raises NotImplementedError. The async version works.
Could ContextEditingMiddleware do this?
No: it clears old tool results, but this one is too big already, on its own.

Why one agent and not a graph?
The agent chooses between three tools by the question. A graph would need us to route by hand.
How does it know which tool?
The dynamic prompt says: course questions to the notes, LangChain code questions to the docs.
Why summarization here?
A long study session grows the context. Above 3,000 tokens the old messages become a summary.
Where is the guard of Day 1?
