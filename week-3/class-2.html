The store
Part 1 · namespace, key, value

A folder per student

store = InMemoryStore() store.put(("ram", "memories"), "food", {"fact": "Ram is vegetarian"}) # namespace, key, value store.get(("ram", "memories"), "food").value # {"fact": "Ram is vegetarian"} store.search(("ram", "memories")) # every piece in Ram's folder
The namespace is the wallRam's facts live in ("ram", "memories"), Sita's in ("sita", "memories"). A search in one folder never sees the other.
Questions that may come up0:10 to 0:25, then you code
What is a namespace?
A tuple that works like a folder path. ('ram', 'memories') is the memories folder of Ram.
What is the key?
The name of one piece in the folder. Saving with the same key replaces it.
Can search find by meaning?
With an embedding index, yes. Without one, search lists the folder (and can filter). We use the list.
What is the value?
A Python dictionary. Here one field, fact.
Memory tools
Part 2 · ToolRuntime

The model chooses the fact. Your code chooses the student.

@dataclass class Context: user_id: str @tool def save_memory(fact: str, runtime: ToolRuntime[Context]) -> str: """Save one short fact about the student.""" runtime.store.put((runtime.context.user_id, "memories"), fact, {"fact": fact}) return "Saved: " + fact memory_agent.invoke({"messages": "..."}, config, context=Context(user_id="ram"))

The model sees only fact. runtime is filled in by LangChain, with the user id your code gave, so the model cannot open another student's folder.

Questions that may come up0:25 to 0:45, then you code
What is ToolRuntime?
An extra argument that LangChain fills in: the store, the context, the state. The model never sees it.
What is a dataclass?
A small class that only holds named values. Context holds the user id.
Why not let the model pass the user id?
A user could say 'I am Sita' and read her memories. The id must come from your login, not from the chat.
What does the agent need?
store=store, context_schema=Context, and context=... on every call.
A dynamic prompt
Part 4 · built before every call

The memories go into the prompt

@dynamic_prompt def personal_prompt(request): items = request.runtime.store.search((request.runtime.context.user_id, "memories")) facts = "" for item in items: facts = facts + "- " + item.value["fact"] + "\n" return "You are a study assistant. What you know about this student:\n" + facts

In our test the agent answered "Your exam is on 1 December" in a new thread, without calling any tool.

Questions that may come up0:55 to 1:10, then you code
Why not always use the recall tool?
The model may forget to call it. A dynamic prompt gives it the facts every time.
And with 3,000 memories?
Then the prompt would be far too long. Use a tool that finds only the memories that matter.
What is request?
The model call that is about to happen: its messages, and the runtime with the store and the context.
Is this middleware?
Yes. @dynamic_prompt is a middleware, added with middleware=[...].
